DC-002.107 -- LOS BUILDS DE POC SIN LA EXCLUSION DE LOOKUPS: 1.788.960 B DE REGALO
==================================================================================

Criterio de la tarjeta: (1) ningun build de POC sale sin las palancas del build del motor (la
exclusion de la tabla de objectLookups entre ellas), (2) hay un chequeo que lo caza, y (3) los
tamanos y sha256 de cada POC quedan escritos.

RESULTADO, en tres lineas:

  1. LAS PALANCAS EN UN SOLO LUGAR. `scripts/console/palancas-del-build.sh` es LA fuente de verdad
     de las cuatro exclusiones por NOMBRE (plataforma, arquitectura, marca de carga del host y la
     tabla de objectLookups). Los siete scripts que compilan Go para la consola la PIDEN: los dos
     del motor (`build-motor-all.sh`, `revisar-arbol-gox.sh`) y los cinco de POC
     (`build-mapa-101/102/103/294.sh`, `build-tablas-282.sh`). Ninguno escribe ya su lista.

  2. HAY CHEQUEO, Y MUERDE. `scripts/console/checar-palancas-poc-107.sh`: 40 en verde, 0 en rojo,
     exit 0. Y cada uno de los cinco scripts de POC lleva una GUARDIA adentro: si el `prog.elf`
     que salio tiene un simbolo de datos de 1 MB o mas (el volcado de la tabla), el build FALLA,
     renombra la imagen a `1ST_READ.BIN.CON-LA-TABLA` y sale 1. Probado con el mutante
     `DC_TABLA_LOOKUPS=dentro` en los cinco: exit 1 en los cinco.

  3. LOS NUMEROS (1ST_READ.BIN, medido, antes y despues):

1. QUE SE SACO DE CADA SCRIPT (la segunda fuente de verdad)
-----------------------------------------------------------
  Antes, cada script tenia los `grep -vE` escritos a mano. Copias que habia:

    build-motor-all.sh      las cuatro palancas (era la "buena", la de DC-002.42/.43)
    revisar-arbol-gox.sh    las cuatro, para no llorar por .go que no van al build
    build-mapa-101.sh       3 de 4: LE FALTABA la tabla de objectLookups  <-- el defecto
    build-mapa-102.sh       3 de 4: LE FALTABA la tabla de objectLookups  <-- el defecto
    build-mapa-103.sh       las cuatro (copiadas en DC-002.103, despues de medir el defecto)
    build-mapa-294.sh       3 de 4: LE FALTABA la tabla de objectLookups
    build-tablas-282.sh     3 de 4: LE FALTABA la tabla de objectLookups

  Lo que cuesta la tabla en la imagen, medido con `sh-elf-nm -S`:
    `object_lookup_record_data.go` = UN simbolo de .data de 1.672.892 B (`_go..C3075`, tipo `d`)
    + 116.048 B de sus cadenas = 1.788.960 B de imagen. En el .gox de `d2core/d2records`:
    2.185.576 B sin la tabla  ->  4.663.692 B con ella.

  Ahora el que compila no arma la lista: la pide.
    mapfile -t SRC_P < <(fuentes_del_paquete "$REPO" "$p")
    sh-elf-gccgo $GODC_GOFLAGS -I "$BASE_GOX" -fgo-pkgpath="$PREFIJO/$p" -c "${SRC_P[@]}" -o "$out"

  API de `palancas-del-build.sh`:
    fuentes_del_paquete <repo> <paquete>    las fuentes del build, con las cuatro palancas
    exclusiones_del_build                   el regex completo (lo usa revisar-arbol-gox.sh)
    lookups_fuera_de_la_imagen              true si la tabla va fuera (lo normal)
    lleva_la_tabla_de_lookups <elf|gox>     0 si el binario lleva el volcado (lo que NO queremos)
    palancas_del_build                      la linea que el build deja en su log
    aviso_mutante_lookups                   el recuadro en grande cuando se corre el mutante


2. LA GUARDIA DENTRO DE CADA BUILD (no solo el chequeo de afuera)
-----------------------------------------------------------------
  El chequeo que corre despues sirve si alguien lo corre. Para que no dependa de eso, cada uno de
  los cinco scripts de POC mide el BINARIO que produjo, no la bandera que paso:

    if lleva_la_tabla_de_lookups "$OUT/prog.elf"; then
        echo "   FALLA: $OUT/prog.elf lleva la tabla de objectLookups:" >&2
        ...
        [ -f "$OUT/1ST_READ.BIN" ] && mv -f "$OUT/1ST_READ.BIN" "$OUT/1ST_READ.BIN.CON-LA-TABLA"
        exit 1
    fi

  Medido, con `DC_TABLA_LOOKUPS=dentro` (el mutante) y un arbol de .gox aparte
  (`/tmp/gox108-mut107`, para no dejar el arbol compartido con la tabla adentro):

    mapa-101   exit 1   1ST_READ.BIN.CON-LA-TABLA   7.052.520 B
    mapa-102   exit 1   1ST_READ.BIN.CON-LA-TABLA   7.069.896 B
    mapa-103   exit 1   1ST_READ.BIN.CON-LA-TABLA   7.078.984 B
    mapa-294   exit 1   1ST_READ.BIN.CON-LA-TABLA   7.050.760 B
    tablas-282 exit 1   1ST_READ.BIN.CON-LA-TABLA   6.877.096 B

    y en el log de cada uno:  FALLA: .../prog.elf lleva la tabla de objectLookups:
                              8c50.... 001986bc d _go..C3075

  El renombre es a proposito: el binario gordo NO se queda con el nombre que viaja a la imagen.

    (la de DC-002.88/.89 llevaba la tabla DENTRO). Es la misma corrida de palancas; lo que sale de
