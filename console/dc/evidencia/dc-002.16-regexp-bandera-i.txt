[0] EL ROJO DE PARTIDA (lo que dejo DC-002.15)
=====================================================================================================

Con el mapa nil arreglado, el arranque del motor moria ANTES de main con un panic sin pila que leer:

El tipo (8c4ef00c) esta en el ELF como `_regexp.Error..p` y el valor del panic es un puntero a
`regexp.Error`: un regexp.Compile que fallo. Como es antes de main, lo dispara un

d2core/d2map/d2mapgen/real_maze_gen.go:33 = `(?i)(pre|prev|up|ent|exit)\d*\.ds1$`).

[1] LA CAUSA FINA, MEDIDA (no deducida): EL CORTE DEL PREFIJO
=====================================================================================================

El regexp de la consola es codigo propio (console/dc/std/regexp/regexp.go, 882 lineas) y su Compile
arranca asi:

    p := patron
    if strings.HasPrefix(p, "(?i)") {      // <- el prefijo mide CUATRO bytes: ( ? i )
        r.sinMayus = true
        p = p[3:]                          // <- DEFECTO: deja "i)a"
    }

Medido en el HOST, con el MISMO codigo (la sonda temporal zz_probe216_test.go, ya borrada; los casos
quedaron en el corpus):

    Compile("(?i)a"):
      nuestro err=regexp: sobra )a en (?i)a            go err=<nil>
    Compile("(?i)(pre|prev|up|ent|exit)\d*\.ds1$"):
      nuestro err=regexp: sobra )(pre|prev|up|ent|exit)\d*\.ds1$ en (?i)(pre|prev|up|ent|exit)\d*\.ds1$
      go err=<nil>
    Compile("(?i)[a-z]\d*\.ds1$"):
      nuestro err=regexp: sobra )[a-z]\d*\.ds1$ en (?i)[a-z]\d*\.ds1$     go err=<nil>

`sobra )a` es exactamente lo que deja `p[3:]`: el parser recibe "i)a", lee el literal "i", se planta en
el ')' y el resto queda sin consumir. NO es el parser de banderas, ni las tablas de plegado de unicode,
ni el motor de ejecucion (las tres hipotesis de la tarjeta): es un off-by-one en el corte del prefijo.
Y es del MISMO archivo del que sale el .gox que usa el motor, asi que no hay duda de plataforma: el
host y la consola dan el mismo error (medido en la consola en [4]).

Causa: la comparacion de literales usaba `alternarMayus` EN LOS DOS LADOS:

    func (r *Regexp) igual(a, b rune) bool {
        if a == b { return true }
        if r.sinMayus { return alternarMayus(a) == alternarMayus(b) }   // <- INTERCAMBIO, no plegado
        return false
    }

`alternarMayus` es un INTERCAMBIO de caso (a->A, A->a): es biyectivo, asi que
`alternarMayus(x) == alternarMayus(y)` solo cuando `x == y`. Con eso la bandera (?i) no podia plegar NUNCA
un literal: el patron del motor, ya sin el off-by-one, seguia siendo sensible a mayusculas.
Ninguna suite lo veia porque NINGUN caso del corpus usaba (?i) (13 patrones, todos sin bandera): la
suite estaba verde y el motor paniqueaba igual. Ese era el hueco de fondo de esta tarjeta.

OJO con la clase: en `claseChar.contiene` el INTERCAMBIO si es lo correcto, porque ahi la pregunta es
simetrica ("¿el OTRO caso cae en este rango?") y con eso `[a-z]` acepta "Z". Cambiar esa por el plegado
habria roto `[A-Z]` (plegar 'a' da 'a', que no esta en [A-Z], donde Go dice que si). Por eso el arreglo
agrega una funcion nueva en vez de reemplazar la que ya estaba.
