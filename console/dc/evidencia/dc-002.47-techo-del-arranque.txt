1. EL DEFECTO (el que movia el arranque, y no era la memoria)

`console/dc/std/bufio/bufio.go`, `ReadBytes`: cuando el lector de abajo devuelve BYTES Y ERROR EN LA MISMA
LLAMADA —que es lo que hace el stream del MPQ cuando el resto del archivo entra en un pedido— la version
anterior hacia `if err := b.rellenar(); err != nil { return salida, err }` y TIRABA los bytes que `rellenar`
acababa de dejar en el buffer. Consecuencia medida: una tabla que entra en un solo pedido se leia VACIA.

    LvlWarp.txt = 3.935 B   <o>   buffer 4.096 B  ->  0 filas  ->  el arranque no pide la tabla siguiente

Arreglo (1 linea de logica, igual que el `ReadSlice` de Go): el error se entrega cuando el buffer quedo vacio
(`if b.Buffered() == 0 && b.err != nil { return salida, b.err }`) y `rellenar` solo se llama si no hay error
pendiente. Lo caza `console/dc/std/difftest/dc00247_test.go` (difftest, host):

    arreglo:  3.935 B entra entero         Go=270 registros  d2std=270 registros
